# REQ-0001:内容资产补充与长尾打磨

状态:草案(待评审)
日期:2026-08-04
关联:ADR-0002(能力包架构)

## 背景与定位修正

与 hermes-studio / PiDeck-maestro / CodePilot 的第一性对比结论:

- 功能清单差距已补齐(17 个能力包,真机验证)。
- **不做**自有 agent 运行时:hermes 的 ekko-agent 与我们的 pi 处于同一架构位置,
  自研 vs 复用只是实现选择。选 pi 就是为了不养运行时,这是刻意决策。
- **不做**自建 provider 层:pi 原生多 provider(配置即换),CodePilot 自建是因为它没有这一层。
- 真差距收敛为两项:**领域知识资产**(容器有了、没装货)与**长尾打磨**(用出来的边角)。

现状盘点(已有的管线,本文档只补内容和缺口):

- `pi-resources/resource-scanner` 已识别 pi 全部资源类型:prompts / skills / extensions / themes / agents。
- 能力包 manifest 已有 `tools` 字段占位,但没有任何能力包真正向 pi 回路注入过工具。
- 权限引擎(5 闸)、能力装配(registry + seal)、结构漂移断言均已就位。

## R1 预置提示词库(办公场景)

**需求**:面向非程序员用户,开箱即有一批中文办公提示词,可浏览、搜索、一键使用。

- R1.1 内容:首批覆盖至少 5 类办公场景 —— 公文/邮件写作、表格与数据整理、
  长文总结、中英互译、汇报大纲(PPT 结构)。每类 ≥3 条,含参数占位说明。
- R1.2 格式:落盘为 **pi 原生 prompts 资源**(复用 resource-scanner 识别),
  不发明私有格式;应用打包时随 extraResources 带入,首启动物化到 pi 资源目录。
- R1.3 UX:renderer 侧提示词库入口(浏览 / 搜索 / 一键填入输入框 / 收藏);
  用户自建提示词与预置库同列展示,预置项可隐藏不可删。
- R1.4 验收:全新用户零配置启动后,提示词库非空;选中一条即可发起会话。

## R2 预置技能包(pi skills)

**需求**:预置办公技能,让 agent 开箱就会做常见办公操作。

- R2.1 内容:首批 ≥3 个 pi skill —— 文件批量整理/重命名、CSV/Excel 数据处理、
  文档格式转换(md/docx/pdf 之间)。
- R2.2 分发:技能作为**能力包携带的资源**声明(见 R4),不是散落文件。
- R2.3 验收:真机会话中,用自然语言让 agent 完成上述任一操作,agent 能命中对应 skill。

## R3 首个真内容垂直包(样板)

**需求**:选一个垂直领域,做出第一个"装了货"的垂直包,作为财务/审计/教育等
后续包的端到端样板。样板必须同时含四类内容,证明架构闭环:

| 内容 | 说明 |
|---|---|
| prompts | 领域提示词(≥5 条) |
| skills | 领域技能(≥2 个) |
| 回路内工具 | ≥1 个 pi extension 工具(见 R4) |
| UI 贡献 | uiContributions 挂至少一个领域面板/入口 |

- R3.1 领域选择:**儿童教育 `edu.kids`**(英语 / 数学 / 语文 / 科学)。定位:给家长/
  辅导者的备课与练习工具,孩子在家长陪同下对话练习,非无监管儿童应用。
  - prompts:按科目 ≥5(单词卡、情景对话陪练、应用题引导式讲解、看图写话、
    古诗背诵检查、按龄科普、家庭实验),前置「引导思考、不代做作业」辅导原则。
  - skills:练习卷生成(出题工具产题→排版可打印)、错题本整理(按知识点聚类
    →针对性复习卷)。
  - 回路内工具:`math_worksheet` 确定性出题器(年级/运算/题量/难度→题目+标准
    答案)。**出题判分走代码保真,讲解归因走模型**——包的核心设计原则。
  - UI:学习面板(孩子档案按 workspace 分区、一键出卷、错题本、打印预览)。
  - 安全:零网络权限,仅工作区文件读写;卸载后数据保留、能力零残留。
- R3.2 验收:安装该包 → 会话内 agent 获得领域工具与技能;卸载 → 全部消失,
  通用能力零残留(现有 drift 测试扩展覆盖)。

## R4 能力包装卸货机制(资源物化通道)

**需求**:打通「能力包 manifest → pi 资源目录」的装卸链路,这是 R2/R3 的地基。

- R4.1 manifest 扩展:能力包可声明携带的 pi 资源(prompts/skills/extensions),
  资源文件随包分发。
- R4.2 装卸:启用能力包时物化资源到 pi 资源目录;停用时移除。物化必须幂等、
  可重入(重复启用不重复落盘,升级时覆盖旧版本)。
- R4.3 权限:回路内工具的执行动作走现有权限引擎(5 闸),不开旁路;
  工具声明的权限需求写进 manifest.permissions,安装时展示。
- R4.4 验收:纯函数级测试覆盖物化/移除的幂等性;结构断言保证资源物化
  不绕过权限闸。

## R5 长尾打磨

- R5.1 **WSL 支持**(Windows):检测 WSL 发行版;workspace 可选择 WSL 内路径;
  terminal 能力包可进 WSL shell。验收:在 WSL 内目录开 workspace 并跑通一次会话。
- R5.2 **usage 统计**:按会话/按日聚合 pi 返回的 token 用量,设置页展示;
  仅本地统计,不上报。验收:跑一次会话后能看到非零用量。
- R5.3 微交互清单:随真实使用持续收集(空态、加载态、错误恢复),
  不在本文档预设范围,滚动进小步提交。

## Non-goals(明确不做)

- 自有 agent 运行时(pi 的职责)
- 自建 provider / 模型网关层(pi 原生支持)
- i18n(自用中文)
- telemetry 上报(自用,本地日志足够)

## 优先级与依赖

```
R4(装卸机制,地基)→ R2(技能包)→ R3(垂直包样板)
R1(提示词库)独立可并行
R5.1 / R5.2 独立可并行
```
