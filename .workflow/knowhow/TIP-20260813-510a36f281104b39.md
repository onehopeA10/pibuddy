When implementing unattended Goal-like loops on PiBuddy, never keep a background pi session alive across wakes.

Each wake must be: requestSession(origin:task) → one agent_settled → stopSession.

Why: evaluateScheduledPermissions only sees workspace grants. A warm session can still hold once/session grants and skip the 2-minute permission inbox reject. That turns “user clicked allow-once in an interactive chat” into overnight authority.

Falsify: a Goal with max_turns=5 whose wake-2 needs a permission that exists only as a session grant must block, consume the turn, and never start wake-3.
